# 01. 기존 시스템(jammanbo / jammanbo-beta) 읽기 전용 실사

작성: 2026-10-24 · 방법: 이 대화에서 이미 읽은 로컬 파일과 프로젝트 기록만 사용. **이번 작업에서 기존 저장소·GAS·시트에 어떤 쓰기도 하지 않았음.**
실제 배포 ID·문서 ID·키 값은 적지 않음(마스킹).

## 확인됨 · 미확인 · 추정

| 항목 | 상태 | 확인 내용 | 신규 프로젝트 처리 |
|---|---|---|---|
| 저장소 | 확인됨(로컬 사본) | `jammanbo`, `jammanbo-beta` 두 저장소, 같은 계정. 빌드 도구·package.json 없음(정적 파일 직접 커밋). 기본 브랜치 `main` | 신규 저장소 `monster-grow`(이름은 가정), Vite 빌드 + Actions |
| Pages | 확인됨 | 프로젝트 사이트 `https://<계정>.github.io/jammanbo/`, `/jammanbo-beta/`. 브랜치 배포(main / root). 사용자 지정 도메인 없음 | 신규 Pages, **GitHub Actions 배포** |
| 같은 출처(origin) | 확인됨 — **주의** | 같은 계정 아래 프로젝트 사이트는 모두 `<계정>.github.io` 한 출처 → localStorage·IndexedDB·Cache Storage 를 **공유** | 새 키 접두사 `mkg_<env>_`, 서비스 워커 쓰지 않음(MVP), 쿠키 쓰지 않음 |
| 서비스 워커 | 확인됨 | jammanbo 는 `sw.js` (범위 `/jammanbo/`, `/jammanbo-beta/`), 캐시 이름 `jmb-static-…` | 신규 프로젝트는 등록 안 함 → 경로 `/monster-grow/` 는 기존 워커 범위 밖 |
| 브라우저 저장소 | 확인됨 | 키 `jmb_*` (화면 코드·데이터·로그인·닉네임 등) | `mkg_local_`, `mkg_staging_`, `mkg_prod_` 접두사. `jmb_` 키를 읽거나 지우지 않음 |
| GAS | 일부 확인 | 웹 앱(실행 = 소유자, 액세스 = 모든 사용자), doGet 화면/데이터 + doPost `{fn,args}` 허용 목록, 운영·테스트 배포 2개, 카카오 로그인(Kakao.gs), 시트 바인딩 | 신규 GAS 프로젝트(신규 시트에 바인딩). 코드 복사 없음 |
| Sheets | 일부 확인 | 모임·회원·게임 기록 등 탭, 1행 제목으로 열 찾기 | 신규 문서, 탭 10개(11_시트_스키마) |
| 인증 | 확인됨 | 카카오 로그인 + 운영진 비밀번호 | 게스트 + 복구 코드, 세션 토큰(HMAC). 카카오 앱·키 재사용 안 함 |
| 운영 권한 | 미확인 | 운영 계정 구성·2단계 인증 여부는 모름 | 신규 운영 API 키(해시만 저장), 편집기 함수 |
| 할당량 공유 | 추정 | 같은 Google 계정으로 GAS 를 돌리면 계정 단위 할당량(실행 시간·트리거·UrlFetch 등)을 함께 씀 | 운영 격리가 중요하면 **신규 Google 계정**으로 GAS·시트 소유 (02_독립운영_경계 참고) |

## 점검 결과 (기존 시스템에서 눈에 띈 위험 — 이번 작업과 무관, 참고용)
- 정적 사이트에 GAS 주소가 공개되는 구조: 정상(공개 값). 비밀 값은 스크립트 속성에 있다고 기록됨 — 직접 확인은 안 함
- 클라이언트 신뢰형 보상·재화 계산: 해당 없음(게임 아님)
- 전체 시트 스캔: 기존 getData 는 캐시 사용 기록 있음 — 세부 미확인

## 하지 않은 것
- 기존 저장소 파일 수정·삭제, Pages/Actions 설정 변경, 기존 GAS 업로드·재배포, 기존 시트 읽기·쓰기 — **없음**
