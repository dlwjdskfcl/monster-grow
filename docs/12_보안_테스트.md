# 12. 보안 · 부정 방지 · 테스트

## 서버 권위 (클라이언트가 할 수 없는 것)
| 위조 시도 | 막는 곳 |
|---|---|
| 재화·보상량을 보냄 | payload 의 그런 값은 아예 읽지 않음. 서버가 settle()·비용표로 계산 (테스트: `위조된 보상량·재화는 무시`) |
| 기기 시각 조작 | 경과 시간 = 서버 시각 − lastSettledAt. 음수는 0, 상한 있음 |
| 같은 보상 두 번 | requestId 중복 무시 + revision + lastSettledAt 같은 상태 변경 안에서 갱신 |
| 보스 승패 조작 | 서버가 전투 시뮬레이션. seed 는 서버 비밀값 기반 |
| 남의 계정 | playerId 는 토큰에서만 꺼냄(본문 playerId 무시). 토큰 = HMAC 서명 + 30일 만료 |
| 복구 코드 대입 | 계정별 10분 5회, 전체 10분 60회. 코드는 해시로만 저장 |
| 요청 폭주 | 플레이어당 분당 60회(설정 가능), 가입 10분 30회, 운영 API 10분 20회 |
| 큰 본문·이상한 JSON | 16KB 제한, 모양 검사, times ≤ 100, 별칭 12자·특수문자 제거 |
| 시트 수식 주입 | 사용자 문자열은 별칭뿐 — `= + @` 등 제거. 시트에는 JSON 문자열(텍스트 서식)로만 저장 |
| 비밀 값 노출 | 프론트에는 공개 API 주소만. 비밀 값 4개는 스크립트 속성. 빌드·backend 비밀 값 검사(`npm run scan`, CI) |
| 운영 기능 남용 | 일반 API 와 분리, 키 해시 비교, 감사 기록 |

localStorage 의 캐시는 **보여주기용**. 손으로 고쳐도 다음 서버 응답에서 덮어씀. Base64·체크섬 같은 난독화는 쓰지 않음(보안 효과 없음).

## 알려진 한계
- 빈도 제한은 CacheService 카운터 → 근사치(동시 실행 시 조금 넘을 수 있음)
- 토큰 폐기 목록 없음 → 토큰 유출 시 만료(30일)까지 유효. 대응: SESSION_SECRET 교체 = 전원 재로그인(복구 코드 필요) — **미구현: 개별 폐기**
- 게스트 계정은 복구 코드를 잃으면 복구 불가 (화면에 안내)

## 아직 실행하지 않은 테스트 (통과로 보지 않음)
- **실제 GAS·시트**에서의 동작 (가짜 환경은 할당량·실행 시간·동시 실행·302 리디렉션을 흉내 내지 않음)
- 통신 실험(05 문서), 실제 iPhone Safari·안드로이드·카카오톡 인앱 브라우저
- 느린 네트워크, 저사양 기기, 네트워크 끊김 중 큐 재전송(코드는 있음, 자동 테스트 없음)
- **부하 테스트**: 스테이징에서만, 5 → 20 → 50명 단계로. 측정: 평균·최대 지연, 오류율, LOCK_FAIL·VERSION_CONFLICT 수, 일일 호출 수 (Metrics 시트) → 그때의 Apps Script 공식 할당량 문서와 비교. 숫자 한도는 계정 유형·시점마다 달라서 여기 고정하지 않음
  - 주의: 모든 쓰기가 스크립트 잠금 하나를 거치므로 **동시 쓰기는 한 줄로 줄 섬**. 요청 하나가 0.5~1초라면 초당 1~2건 수준이 상한일 수 있음(추정) → 측정 필요. 넘으면 플레이어별 시트 분할·잠금 범위 축소 검토
