# 13. 운영 · 백업 · 복구 · 마이그레이션

모두 **GAS 편집기에서 함수 이름을 골라 실행** (운영 API 로도 일부 가능).

## 트리거 설치 (처음 한 번)
`installTriggers()` → 지표 정리 1시간 · 운영 사본(Inventory/Collection) 1시간 · 백업 매일 04시(KST)

## 점검 · 읽기 전용
| 상황 | 실행 | 효과 |
|---|---|---|
| 배포·시트 작업 전 | `setReadOnly(true)` | sync 만 됨, 저장 명령은 READ_ONLY |
| 점검 | `maintenanceOn()` / `maintenanceOff()` | 모든 게임 요청 MAINTENANCE, 화면에 점검 안내 |
| 오래된 화면 차단 | 운영 API `setConfig minClientVersion 0.2.0` | 낮은 버전 요청 거부 → 새로고침 안내 |
| 공지 | 운영 API `announce` 또는 Announcements 탭에 직접 한 줄 (enabled=Y) | 2분 캐시 |
| 이벤트 배율 | GameConfig `prodMult` (0.1~10) | 60초 안에 적용 |

## 백업
- 자동: 매일 `backupSnapshot()` → 새 스프레드시트 `몬스터키우기_백업_<env>_<시각>` (내 드라이브)
- 수동: 큰 작업 전에 `backupSnapshot()`
- 보관: 오래된 백업은 드라이브에서 직접 정리(자동 삭제 없음 — 미구현)

## 복구 리허설 (스테이징에서 분기마다)
1. `setReadOnly(true)`
2. 백업 사본의 PlayerState 탭 전체를 복사 → 스테이징 시트 PlayerState 에 붙여넣기 (Players 도 같은 범위로 — **행 순서 유지**)
3. 캐시 비우기: 편집기에서 `CacheService.getScriptCache().removeAll(['cfg','ann'])` + 행 캐시는 6시간 내 자동 검증(행이 안 맞으면 TextFinder 로 다시 찾음)
4. `reconcile()` → CommandJournal 보충 수 확인
5. 게임에서 sync → 백업 시각 상태가 보이는지
6. `setReadOnly(false)`
⚠ 복구하면 백업 이후 진행은 사라짐 → 플레이어 공지

## 장애 대응
| 증상 | 확인 | 조치 |
|---|---|---|
| SERVER_ERROR(BUSY) 증가 | Metrics.lockFail | 동시 사용자 확인, 잠금 대기 늘리기(LOCK_WAIT_MS), 읽기 전용 전환 |
| VERSION_CONFLICT 많음 | Metrics.conflict | 여러 탭 사용, 클라이언트 재시도 버그 |
| 응답 느림·30초 | Metrics.avgMs/maxMs, GAS 실행 기록 | 콜드 스타트(정상), 시트 크기(Journal 비우기) |
| 상태 손상 | stateHash 경고 로그 | 해당 행만 백업에서 복원 |
| GAS 배포 실수 | 배포 관리 → 이전 버전 | 버전 되돌리기 (URL 같음) |
| 프론트 배포 실수 | GitHub → Actions → 이전 성공 실행 Re-run, 또는 커밋 Revert | |

## 스키마 마이그레이션
1. `shared/state.ts` 의 `SCHEMA_VERSION` +1, `migrate()` 에 단계 추가 (예전 데이터 → 새 모양, 기본값 채우기)
2. `tests/core.test.ts` 에 예전 JSON → 새 상태 테스트 추가, `npm run check`
3. `npm run build:gas` → 스테이징 GAS 에 GameCore.gs 업로드·새 버전 배포
4. 스테이징: `backupSnapshot()` → `runMigrations()` → Migrations 탭 'DONE n / 실패 0' 확인
5. 프론트(스키마 숫자 포함) 배포 — 순서: **서버 먼저**(새 서버는 예전 상태를 읽을 수 있음), 그다음 `minClientVersion` 올리기
6. 운영에서 같은 순서. 읽어 들일 때도 migrate() 가 돌아서 runMigrations 없이도 동작함 — 일괄 실행은 정리용
⚠ 지금 클라이언트는 schemaVersion 이 다르면 거부됨(SCHEMA_MISMATCH) → 스키마 변경 = 클라이언트도 새 버전 필수
